## 共通記法と仮定台帳

任意の有限符号語 σ : `[p,k)` → `{A=+1,S=−1}` を扱う。Recamán実軌道は仮定しない。

```text
F(p)=0, F(u+1)=F(u)+σ(u)
G(p)=0, G(u+1)=G(u)+F(u+1)
P2(t,b) :⇔ p≤t<b, F(b)=F(t)+1, G(b)−G(t)=(b−t)F(t)
Endable_p(b) :⇔ σ(b)=A かつ ∃t∈[p,b), P2(t,b)
d_p(u) = #S[p,u) − #Endable_p[p,u)                 （整数の差）
a_p(x,y) = #{u∈[x,y): σ(u)=A かつ ¬Endable_p(u)}
τ_p(b) = max {t∈[p,b): P2(t,b)}                  （Endableなbだけ）
```

P2窓は `[t,b)`、終点の符号 σ(b)=A は別条件。endableは窓の本数ではなくclockを一回数える。
`a_p(q0,b+1)` の判定基点も p のまま。τ は**最新の始点**（最短窓）、任意の窓の始点とは異なる。
Leanとの対応は `Recaman.LineCapacityPeriodic.Endable` と `CapacityEqualityInduction.HCap/EqClassW`。

C1/C2が消費される **完成した d=1 の設定 D** は次のように明示して固定する。

- `p<q0<c=k−1`、`Endable_p(c)`、`τ_p(c)=q0`、`d_p(k)=0`。
- `d_p(q0)=1`、`a_p(q0,k)≤1`、`q0<u<k` なら `d_p(u)≥1`。
- `p≤u≤q0` なら `d_p(u)≥0`、`k1=max{u∈[p,q0): d_p(u)=0}`（pが含まれる）。
- 最小反例から使う帰納仮定は、`[p,k)` 内の**真部分区間だけ**の H と EqClassW。
  各区間ではその区間の左端からEndableを数える。全区間 H、全区間 EqClassW、C1/C2/TS自体は仮定しない。

これは次unitで検算する適用条件の台帳である。とくに内部 `d≥1` は旧カードの補題T、完成条件からの
Sの予算は補題Fの供給を再確認する。短い区間からの供給が示せなければ、条件付き命題を親の解決と呼ばない。
`k1=p` では C1 の t の範囲は空。`k1>p` のブロック接頭辞は短い等号区間の EqClassW から供給する。
k1直前がendableとは限らないため、最後のendableまでの等号区間と、その後のA列を分けて確認する。

  広い集合の検査は狭い集合の反証検査にも使えるが、コメントと集計名だけでは同一命題と認めない。

## 継続・切替の規則

1. C2の15分確認点で仮定供給と主張・probeの包含関係を確認できなければ、一様証明に進まず不足入力を残す。
   残り45分はC2へ自動延長せず、C1に20分・TSに25分を移す（活用15・探索75・監査10）。
2. C2′だけが反証された場合、元versionを `REFUTED` として保存する。完成したC2への修理は一回だけ、
   同じ60分枠内で許す。C2自体の反例でなければ親のC2やSLを反証済みにしない。
3. 一様な紙上証明と仮定供給が揃った場合、次unitを最小Lean statementの意味監査・形式化にする。
   結論を仮定した補題や長さ上限の拡張だけなら継続せず、当該方法を停止する。
4. C1の15分では未知edgeを一つにする。Qを結論の別名で仮定しただけなら活用へ昇格させない。
   TSの15分では漏れの鎖を扱う新しい入力の候補を一つまで。候補がなければ有限表拡張の停止を維持する。
5. 二cycle続けて同じ障害で候補集合もedgeも変わらない場合、次cycleを**活用40・探索50・監査10**へ変更し、
   探索50のうち少なくとも25をH経路の既存三候補と異なる機構の評価へ移す。
   [portfolio](RESEARCH_PORTFOLIO.md)の停止枝を検索し、再開条件のない再走を避ける。
