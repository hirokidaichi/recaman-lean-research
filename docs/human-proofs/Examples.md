# Examples

**役割:** 主要な定義と定理を、Lean カーネルの `decide` で検証された小さな具体例・反例で確認する。

## このモジュールの役割

抽象的な機構 (初出、blocker、目標方程式、借りデータ、完全ゲート) が実軌道の具体的な数値で意図どおりに動くことを、計算による証明で固定する検証層である。ここの例は二つの役割を持つ。第一に、定義の健全性チェック (blocker 証明書が実際に構成できる、座標遷移則が実軌道の値と一致する)。第二に、仮定の鋭さの証明 (直接目標方程式は `m = 1` ですでに破綻する、多段借りの時刻下界や完全ゲートの中間値条件は落とせない)。計算実験ではなく、すべて Lean カーネルが検証する定理である。参照する数列の冒頭は `a = 0, 1, 3, 6, 2, 7, 13, 20, 12, 21, 11, 22, 10, 23, 9, 24, …` である。

## 定理と証明

### `firstAt_seven` (L5)

**主張:** 値 7 の初出時刻は 5 である: `FirstAt a 7 5`。

**証明:** `a 5 = 7` は計算で確認し、`u < 5` の各時刻について `a u` (0, 1, 3, 6, 2) が 7 でないことを一つずつ `decide` で確かめる。

### `firstAt_three` (L28)

**主張:** 値 3 の初出時刻は 2 である: `FirstAt a 3 2`。

**証明:** 同様に `a 2 = 3` と `a 0, a 1 ≠ 3` の計算による。

### `actualBlocker_at_five` (L43)

**主張:** `ActualBlocker 5 7 0 1`。すなわち時刻 5 の初出値 7 から始まる下降は、長さ 0 の時点 (つまり出発直後) で既出値 1 に妨害される。

**証明:** blocker 証明書 (ActualBlocker: 初出、下降列、次の減算候補が正であること、その候補の値、候補が既出であること、の五条件) を成分ごとに確認する。初出は `firstAt_seven`、長さ 0 の下降列は自明、候補は `7 − 6 = 1` で正、そして 1 は `a 1 = 1` として履歴に既出である。直後の無名 `example` (L54) は、この証明書から `1 < 7` と「1 の初出が 5 より早い」という二重下降 (値も初出時刻も真に減る) が取り出せることを確認する。

### `targetAttempt_seven_to_one` (L59)

**主張:** `TargetOutcome 5 7 1 1`。すなわち初出値 7 (時刻 5) から目標 1 への 1 歩の下降試行は、「着地」か「blocker で停止」のどちらかである。

**証明:** 目標方程式 (TargetEquation: `m + descentDrop f k = v`、ここで `descentDrop f k = k·f + U(k)` は `k` 歩連続減算の合計降下量) が `1 + (1·5 + 1) = 7` として成り立つので、下降二分法 `targetDescent_dichotomy` を適用するだけである。

### `targetAttempt_seven_to_one_is_blocked` (L65)

**主張:** 上の試行は実際には blocker 側である: `∃ length y, length < 1 ∧ ActualBlocker 5 7 length y`。

**証明:** 着地側なら `a 6 = 1` のはずだが、計算により `a 6 = 13 ≠ 1` なので排除される。残る blocker 側の証人 (実体は L43 の length 0, y = 1) が結論を与える。方程式が予言する `7 − 6 = 1` への降下が、1 の既出により実行できない最小の実例である。

### `no_targetEquation_three_to_one` (L76)

**主張:** どの歩数 `k` についても `TargetEquation 2 3 1 k` は成り立たない。すなわち初出値 3 (時刻 2) から目標 1 への目標方程式 `1 + 2k + U(k) = 3` に解はない。

**証明:** `k = 0` では左辺 1、`k = 1` では左辺 4 であり、`k ≥ 1` で左辺は単調増加するから、3 に一致する `k` は存在しない。

### `not_targetResolvable_one` (L87)

**主張:** `¬ TargetResolvable 1`。ここで `TargetResolvable m` は「`m` より大きいすべての初出値から `m` を狙う目標方程式が立てられる」という素朴な直接下降条件である。

**証明:** `TargetResolvable 1` を仮定し、初出値 3 (時刻 2、`firstAt_three`) に適用すると、ある `k` について `TargetEquation 2 3 1 k` が得られるが、これは前定理に矛盾する。素朴な直接目標戦略が最小の目標 `m = 1` で既に破綻すること、したがってゲート・脱出・回復などの追加機構が必要であることを示す反例である。

### `smallestCounterexample_coordinateTrace` (L96)

**主張:** その最小反例の周辺 4 時刻の座標トレース:

```text
時刻 2: (q,r) = (1,1), G = 0     (a 2 = 3)
時刻 3: (q,r) = (2,0), G = −3    (a 3 = 6, 強制加算)
時刻 4: (q,r) = (0,2), G = 2     (a 4 = 2, 一段借り減算)
時刻 5: (q,r) = (1,2), G = 1     (a 5 = 7, 強制加算)
```

**証明:** 時刻 2 の座標を `decide` で確認した後は、`CoordinateDynamics` の遷移定理を実際の分岐に沿って順に適用する: `q ≤ r` の通常加算 (G は `2q+1 = 3` 低下)、`r < q` の一段借り減算 (G は `n+q = 5` 上昇)、通常加算 (G は `2·0+1 = 1` 低下)。各ステップのポテンシャル値は計算で照合する。座標力学の四遷移が実軌道の値と正確に噛み合うことの見本である。

### `threeBorrow_arithmetic_example` (L117)

**主張:** 借り 3 回の純算術例。`n = 3`, `q = 10`, `r = 1` (値 31) の借りデータは `b = 3`, `s = 3` であり、法 4 での加算は `QuotRem 4 35 8 3` (商 `q+1−b = 8`)、減算は `QuotRem 4 27 6 3` (商 `q−1−b = 6`) となる。ポテンシャルはそれぞれ `G(10,1) + 21`、`G(10,1) + 36` に一致する。

**証明:** 収支等式 `3·4 + 1 = 10 + 3` を含め、全成分を `decide` で検証する。`MultiBorrow` の一般算術モデルが `b ≥ 2` でも整合的に動くことを示す例だが、`OrbitBounds` によりこの配置は実軌道上には現れない。

### `earlyMultiBorrow_subtraction_exception` (L135)

**主張:** 時刻 2 の非軌道算術状態 `n = 2`, `q = 4`, `r = 0` (値 8) は借り 2 回のデータ `b = 2`, `s = 2` を持ち、減算後は `QuotRem 3 5 1 2` で正の目標レベル `G(1,2) = 1` に着地する。

**証明:** 全成分 `decide` による。抽象的な「多段借り減算は負性をもたらす」型の定理に付く時刻下界 `n ≥ 4` の仮定が鋭いことを示す反例であり、この例外的配置は別定理 `actual_multi_time_ge_four` によって実軌道から排除される。

### `targetSurface_two_fresh_target_but_blocked` (L147)

**主張:** 時刻 18 で `CoordinatesAt 18 2 7` (a 18 = 43)、`G(2,7) = 4`、目標レベル 4 自体は未出だが、完全ゲートの中間値 `gateIntermediate 18 4 = 24` は既出であり、次の一歩は加算になって `a 19 = 62`。

**証明:** 全成分 `decide` による。減算候補 `43 − 19 = 24` は時刻 15 に出現済みなので減算は封じられる。目標面 (`G = m`) に乗り、目標自身が新鮮でも、`Gate` の `exactGate_sufficient` が要求する中間値の新鮮さを落とすとゲートが開かない、という最小の警告例である。

## 全体の中での位置づけ

証明地図のモジュール層「検証」に属する。`LandingSurfaces` までの定義 (blocker、下降、目標方程式) と `Gate`・`MultiBorrow` の機構を対象に、健全性の確認と仮定の鋭さの証明を同時に行う。ここで確立された反例、特に `not_targetResolvable_one` は、直接下降だけでは全射性に届かないこと、すなわち証明地図の「目標面」以降 (ゲート、回復、エポック、大域探索) の全機構が必要であることの動機付けそのものである。方針文書 (docs/PROOF_MAP.md 末尾) が述べるとおり、具体例の検証はすべて Lean カーネルの `decide` で行い、計算実験の結果を証明の仮定に使わないという境界を守っている。
