# 人間向け証明レポート スタイルガイド

`docs/human-proofs/<ModuleName>.md` は、対応する `Recaman/<ModuleName>.lean` を
Leanを読まずに理解できるようにする日本語の証明ドキュメントである。
想定読者は数学科の学部生程度(Leanの知識は仮定しない)。

## ファイル書式

```markdown
# <ModuleName>

**役割:** 1行要約

## このモジュールの役割

2〜5文。プロジェクト全体(全射性予想への攻略)の中でこのモジュールが
担う位置づけを説明する。

## 主要な定義

(def / structure / inductive がある場合のみ)

### `DefName` (L12)
日本語での意味の説明。

## 定理と証明

### `theoremName` (L42)

**主張:** 定理の内容を日本語の数学文として述べる。

**証明:** 人間向けの証明。Leanのタクティクの逐語訳ではなく、
数学の論文・教科書に書くような議論として書く。場合分けの構造、
帰納法の対象、鍵となる不等式を明示する。自明に近い補題は1〜2文でよい。
中核的な定理は段落を分けて丁寧に書く。

## 全体の中での位置づけ

このモジュールの結果がどのモジュールから使われ、
証明地図(docs/PROOF_MAP.md)のどの段階に対応するか。
```

## 規則

- **見出しの定理名・定義名の直後に必ず ` (L<開始行番号>)` を付ける。**
  行番号は `grep -n` で実ファイルから取得した正確な値を使う
  (ビューワーがこの行番号でLeanソースへジャンプする)。
- 数式はLaTeXではなく**Unicode**で書く: `a(n)`, `≤`, `⌊r/2⌋`, `∀`, `∃`, `¬`, `→`。
  インライン数式・識別子はバッククォートで囲んでよい。
- 用語は `docs/GLOSSARY.md` に従う。研究固有用語(potential, borrow, blocker,
  epoch, debt, crossing, anchor, horizon など)は初出時に一言説明を添える。
- 定理は原則すべて記載する。ただし純粋に技術的な補助補題は
  「補助補題」として1〜2文でまとめてよい。
- Leanソースには一切手を加えない。出力はこのディレクトリのMarkdownのみ。
