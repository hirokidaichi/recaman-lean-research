# DebtAddition

**役割:** 強制加算で生まれた初出値から減算候補を回収する二分法を証明し、目標下界・anchor下界が強制加算だけからは従わないことを実例で示す。

## このモジュールの役割

debtノードの一歩解析(`DebtStep`)の強制加算枝で必要になる算術的部品を供給するモジュールである。時刻`n+1`の遷移が強制加算になるのは、減算候補 `a(n) − (n+1)` が非正であるか、すでに履歴に出現している場合に限る。後者の場合、その候補は「より早い初出時刻を持つ、より小さい値」として回収でき、debt再帰の材料になる。ただし本モジュールの後半は、この候補が目標以上であることも、anchor未満であることも、強制加算だけからは導けないことを、実軌道上の反例をLeanカーネルの`decide`で検証して示す。これにより、debt再帰に必要な追加仮定がどこで別途供給されねばならないかが確定する。

## 定理と証明

### `not_canSubtract_iff_nonpositive_or_seen` (L9)

**主張:** 任意の状態で、減算不可能であることは「候補が非正(`¬ stepIndex < state.value`)」または「候補 `state.value − stepIndex` が既出集合に含まれる」ことと同値である。

**証明:** `CanSubtract`の定義(候補が正、かつ未出)の否定をド・モルガン的に展開するだけである。実軌道に限らない状態レベルの形で述べてある点が再利用性の要である。

### `firstAt_forcedAddition_dichotomy` (L31)

**主張:** `y`が時刻`n+1`に初出し、その遷移が強制加算だったとする。このとき、候補が非正(`¬ n+1 < a(n)`)であるか、さもなければ候補 `x = a(n) − (n+1)` は正で、ある時刻 `fx < n+1` に初出し、かつ `x < y` を満たす。定理は目標下界やanchorとの関係を一切主張しない — それらは強制加算の帰結ではないからである。

**証明:** `n+1 < a(n)` の場合、前補題により候補は既出でなければならない。履歴の元は初出時刻を持つので `fx ≤ n < n+1`。また強制加算より `y = a(n) + (n+1)` なので、`x = a(n) − (n+1) < a(n) < y` が従う。`n+1 ≥ a(n)` の場合は第一枝である。

### `firstAt_forcedAddition_extract_candidate` (L60)

**主張:** さらに `n+1 < a(n)`(候補が正)が分かっているなら、二分法の第二枝が必ず成り立ち、候補とその早い初出時刻が直接取り出せる。

**証明:** 二分法を適用し、非正枝を仮定と矛盾させて消すだけである。

### `firstAt_forcedAddition_extract_candidate_above_target` (L74)

**主張:** debt再帰に必要な目標下界 `m ≤ x` は、候補について別途 `m ≤ a(n) − (n+1)` が分かっているとき、そしてそのときに限り付加できる。

**証明:** 前定理で候補を取り出し、仮定した下界をそのまま添える。1行の合成である。

### `firstAt_forcedAddition_extract_candidate_below_anchor` (L89)

**主張:** 同様に、anchor下降によるdebt脱出に必要な `x < anchor` も、候補とanchorの比較 `a(n) − (n+1) < anchor` を別途仮定して初めて得られる。

**証明:** 前定理との合成である。

### `forcedAddition_target_bound_not_automatic` (L132)

**主張:** 目標下界は自動では成り立たない。実軌道の一歩 `a(5) = 7 → a(6) = 13`(強制加算、`13`は時刻6に初出)は、目標`8`に対して `8 ≤ 13` を満たすのに、候補 `a(5) − 6 = 1` は `8 ≤ 1` を満たさない。

**証明:** 補助補題(`debtAddition_firstAt_thirteen`、L105、private)が `FirstAt a 13 6` を示す: `a(6) = 13` は`decide`で計算でき、時刻0〜5の各値が13でないことも`decide`で個別に確認する。残る主張(減算不可能性、数値比較)もすべて`decide`によるカーネル検証である。

### `forcedAddition_anchor_bound_not_automatic` (L140)

**主張:** anchor比較も自動では成り立たない。同じ一歩で、候補`1`はanchor`1`より真に小さくない(`¬ a(5) − 6 < 1`)。

**証明:** 前定理と同じ実例を`decide`で検証する。

## 全体の中での位置づけ

証明地図の「負債・crossing閉包」段階の強制加算側の算術基盤である。二分法 `firstAt_forcedAddition_dichotomy` は `DebtStep` の分類定理 `debtStep_classify` に直接使われ、crossing障害 `addition_nonpositive` / `addition_seen_below_target` の証拠を供給する。二つの反例定理は、`DebtStep`や`DebtCrossing`で目標・anchorに関する枝分かれが仮定として明示されている理由を説明するものであり、「強制加算そのものは目標との位置関係について何も約束しない」という設計上の境界をカーネル検証付きで固定している。
