# prefix-successor coverage の漸近的生存可能性（2026-08-29 数値実験）

`ReplayPrefixSuccessorCoverage` によるreplay固定点排除が cutoff（= kernel 射程）を
伸ばしたときどこまで clock 床を上げられるかを測った。**このディレクトリの成果物は
経験的なガイドであり、Lean 証明には一切使われていない。**

## 中心となる再定式化

coverage の定義（cutoff は時刻と値の両方の上界）から、最小 witness は
`first[s]`（値 `s` の初出時刻）である。したがって

```
Need(clock) := max over v in { a t : t < clock, v > a clock }  of  max(v + 1, first[v + 1])
```

とおくと **`coverage(clock, cutoff)` ⟺ `Need(clock) ≤ cutoff`**。`Need` は cutoff に
依存しないので、一度計算すれば全 cutoff に対する

```
C(cutoff) = (Need > cutoff となる最小の eligible clock) − 1
```

が同時に読み取れる。既存の `replay_prefix_successor_coverage.cpp` は cutoff ごとに
O(Cmax²) 走査するが、この形なら segment tree の suffix-max で O(Cmax log) で済む。

## プログラム

| ファイル | 役割 |
|---|---|
| `deep_first.cpp` | 厳密履歴 bitset で N ステップ流し、値 `≤ M` の初出時刻表を binary 出力（途中 checkpoint あり） |
| `coverage_scan.cpp` | 初出表を読んで全 eligible clock の `Need` を計算し、record（走行最大の更新点）を出力 |
| `coverage_need.cpp` | 上記の自己完結版（初出表の生成も内蔵、小さい Cmax 用） |
| `fixedpoint_survivors.cpp` | replay 固定点の必要条件 (2)(3)(4)(5)(6) を満たす `(C, T)` 対の国勢調査 |

```bash
clang++ -O3 -std=c++20 deep_first.cpp -o deep_first
./deep_first 10000000 50000000000 first_5e10.bin 5000000000     # 約 80 秒 / 約 50GB
clang++ -O2 -std=c++20 coverage_scan.cpp -o coverage_scan
./coverage_scan first_5e10.bin 10000000 1000000 112 out
```

生成された巨大な中間データ（`first_5e10.bin` = 80MB、`*_all.csv` = 数十MB）は
リポジトリに置いていない。ここには要約だけを置く。

## 主結果 3: 天井（機構そのものの限界）

clock 53906 は「anchor 167475 の上に prefix 値 167476（初出 t=53904）が居るのに、その
後続 167477 が 5×10^10 ステップまで一度も出現しない」という理由で詰まっている。
これは cutoff を伸ばせば済む話ではなく、初出深度の裾が重いという構造的な性質による。

初出深度比 `r(v) = first[v]/v` の裾（`v ∈ [10^6, 10^7]`、`first_occurrence_depth_tail.csv`）:

| K | P(r > K) | 局所裾指数 α |
|---:|---:|---:|
| 10 | 0.1440 | — |
| 100 | 0.0228 | 0.64 |
| 1 000 | 0.0106 | 0.27 |
| 10 000 | 0.0065 | 0.14 |
| 30 000 | 0.0062 | 0.05 |

α が 0 に落ちる = 裾がほぼ平ら。**値のおよそ 0.6% は実用的な地平線の外に初出を持つ。**
prefix の「anchor より上の値」の個数は clock にほぼ比例して増える（`k ≈ 0.17·C`）ので、
clock が大きくなるほど「深すぎる後続」を 1 個は掴む確率が 1 に近づく。

その帰結（`cutoff_survivors.csv`、Cmax = 10^6 の eligible clock 213 719 個）:

## 主結果 4: 固定点の他の必要条件は絞り込みに寄与しない

`fixedpoint_survivors.cpp`（Cmax = 10^6、地平線 5×10^10）:

- 条件 (2) `C+1 < a(C)` を満たす clock: 713 728
- 条件 (2)+(3)（強制加算）を満たす clock: 213 739
- そのうち、帯 `(a C, a(C+1)]` に「地平線内で未出の target」を含む clock: **212 479（99.4%）**
- record crossing でないもの: 212 460
- 生き残る `(C, T)` 対の総数: **4.33×10^8**（clock decade ごとに 148 → 5 382 → 1.33×10^6 → 4.32×10^8 と超線形に増加）

つまり「crossing が record でない」条件は 213 739 のうち 22 個しか落とさず、target の
未出条件も帯幅が `C+1` で伸びるため**絞り込みにならない**。反例候補の探索空間は
clock とともに広がる一方で、力学的排除の方が先に息切れする。

## 判定

**(b) ある地点で急激にコストが爆発して事実上停止する。**

爆発点は明確で二段構えである。

1. **実務的な停止点は clock 24 260 → 53 905 の一段**（必要射程 1.8×10^7 → 2.8×10^9）。
   現状の Lean kernel は clock 112 の障害である `a 4825 = 371` すら未検証なので、
   ここまで来る前に止まる。射程 10^5 でも床は 776、10^7 でも 13 507 にしかならない。
2. **機構そのものの天井は clock ≈ 5.4×10^4**。clock 53906 は射程 5×10^10 でも越えられず、
   さらに clock 10^6 までの eligible clock の 65% は射程無限大でも coverage の
   守備範囲外である。これは cutoff の問題ではなく、Recamán の初出深度の裾が
   α ≈ 0 の重い裾を持つことに由来する構造的な限界。

したがって、**深部検証（kernel 射程延長）への投資は正当化されない**。
床上げは 1 ラウンドごとに必ず成功するが、`target ≥ 114` を `target ≥ 10^3` にするだけで
射程 ~10^6、`10^4` にするには ~10^8 が要る（`X ≈ 0.05·C^2`）。全射性の定理に到達するには
clock を無限に上げる必要があるが、この機構は clock 5×10^4 付近で数学的に停止する。
別の終端構造の排除（coverage に依存しない議論）へ切り替えるべきである。
